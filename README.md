# tadori（辿り）

> ⚠ **着手前です。**コードはまだありません。置いてあるのは方向性（[PRD.md](PRD.md)）と最初の段取りだけです。

**仕様の 1 文から、試験ケース・実施の証跡・指摘・再発防止までを ID でつなぐ、git 上の台帳。**
「どこが保証されていないか」を AI が洗い出し、人が確かめます。

## なぜ作るか

不具合が出たとき、「当時気づけたのか」「なぜ試験で拾えなかったのか」を説明するには、
設計書・試験書・課題票・レビュー・会話ログの 4〜5 か所を掘り返すことになります。
**記録はあります。記録どうしのつながりが人の頭の中にしかありません。**

AI に開発を任せる比率が上がるほど、AI が何を根拠に「確かめた」と言ったのかを
後から辿れることが要ります。

## するもの

| コマンド | 出すもの |
|---|---|
| `tadori check` | つながりの穴（ケースの無い仕様の文・証跡の無いケース・仕様の変更より古い証跡・再発防止の無い指摘・存在しない ID） |
| `tadori why <ID>` | その 1 件から上下に辿った全部 |

台帳は git 上の TSV / Markdown です。tadori が無くても人が読めます。

## やらないこと

- 課題管理・試験の実行・文書の編集画面（それぞれ既存の道具を使います）
- 品質の点数化・ダッシュボード

## 一緒に使う道具

- [md-business](https://github.com/meta-taro/md-business) — 仕様と検証シート
- [git-qa](https://github.com/meta-taro/git-qa) — 試験の実施と証跡

## 技術スタック（予定）

- Node.js の CLI 1 本（pnpm）
- 台帳は TSV（md-business の検証シートの形に揃える）
