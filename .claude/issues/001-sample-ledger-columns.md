# 001 — 架空の案件で台帳を起こし、列の叩きを作る

## 目的

`check` と `why` のテストに使う見本を作る。同時に、SPEC / F / R の列の叩きを決める。

## やること

- 架空の小さな案件（例: 画面 2 枚の申込フォーム）を 1 つ決める。**実在の案件・顧客・画面名を使わない**（D3 / D7）
- 次の 3 本を `examples/<案件名>/` に置く
  - `spec.tsv` — 仕様の文（ID・本文・根拠・現状／改修後・変わる印）
  - `findings.tsv` — 指摘（ID・要約・出どころ・原因区分・気づけた工程・関係する SPEC / TC）
  - `prevents.tsv` — 再発防止（ID・本文・どの指摘から）
- 検証シートは md-business の形（`#! md-business:test-spec-tsv/v1`）で 1 本。`ケースID` と `covers` 列を足す（D4 の先取り）
- run.json は git-qa の形で 1 本（手書きでよい）
- わざと穴を入れる: ケースの無い仕様の文 1・証跡の無いケース 1・再発防止の無い指摘 1・存在しない ID への参照 1

## 完了条件

- [ ] 上の 5 ファイルが `examples/` にある
- [ ] わざと入れた穴 4 種が、見本の README に列挙してある（002 のテストの期待値になる）
- [ ] 列の定義が `docs/columns.md` に 1 表で書いてある
